# 개발 기록 — 식자재 구매·평가 보드

날짜별 변경과 그때 내린 결정을 남깁니다. 다음에 고칠 사람이 "왜 이렇게 됐는지"를 알 수 있게 하는 것이 목적입니다.
(실제 구매 데이터·가격은 적지 않습니다.)

## 2026-09-23 · 시작
- 출발점은 하네스(전선) R&D용 구매·테스트 대시보드 프롬프트였으나, 실제 사용처에 맞춰 **식자재 샘플 구매·평가**로 전환.
- 테스트 수율·진행/대기 단계는 빼고, 품목마다 **사용 가능 / 추후 사용 / 사용 불가** 판정 + 한 줄 평(태그)만 남김.
- 저장소: Supabase(설문·품질검증과 같은 프로젝트, 테이블은 `pur_` 접두사로 분리). 호스팅: GitHub Pages.
- **로그인 없음**은 사용자 선택. 대신 RLS로 영구 삭제를 막고 삭제는 "보관"으로 처리.
- 동시 편집: 판정은 `ev_ver` 조건부 update로 충돌 감지 → 화면에 "상대 값 유지 / 내 값으로 덮어쓰기" 배너.

## 2026-10-07 · 가격 구조 개편
- **문제**: 총액이 `수량 × 단가`인데 실제 입력은 "봉지 가격"이라, 600g 곤약을 0.6kg × 2,140원으로 넣으면 1,284원이 되는 등 총액이 틀림.
- **결정**: "몇 개 샀나"와 "1개에 뭐가 얼마나 들었나"를 다른 칸으로 분리.
  - 총액 = 구매 수량 × 1개 가격. 내용량(600g, 10장)은 **총액에 절대 곱하지 않고** kg당·장당 환산 단가에만 사용.
- **구매처** 칸 신설(쿠팡·마트 등). 거래처(제조·공급사)와 분리.
- 입고일: 기본값 없이 **필수**, 달력 선택, 미래 날짜 불가. (오늘·어제 버튼안은 사용자가 달력 선택을 원해 채택 안 함)
- 숫자 칸: 0 기본값 때문에 "0125"처럼 입력되던 문제 → 빈칸 시작 + 누르면 전체 선택.
- 기존 데이터는 칼럼 추가(비파괴) 후 값만 옮김. 입고일은 사용자가 직접 수정.

## 2026-10-07 · 보기 정리
- 리스트를 **구매처 → 분류 → 품목** 접기식으로. 검색 중에는 자동으로 모두 펼침. 펼침 상태는 기기에 저장.
- 달력 칸에 구매처별 금액을 **원 단위**(20,000원)로 표시.
- 추가 폼에서 설명 문구·최근 품목 버튼 제거(데이터가 늘면 지저분해짐). 전에 산 품목 자동 채우기는 품목명 자동완성으로 유지.

## 2026-10-08 · 무게 구매와 중복 입력
- **문제**: 구매 단위에 kg이 있어 300g 1봉을 "0.3kg × 2,900원"으로 넣어 870원이 됨.
- **결정**: 입력을 두 모드로 분리.
  - **개수로 샀어요**: 수량은 정수만, 단위는 봉·팩·묶음·단·개·박스·병. 무게는 "1봉에 든 양"에.
  - **무게로 샀어요**: 저울 무게(kg) + **영수증 결제 금액** → kg당 가격 역산 저장. (kg당 가격을 받으면 100g당·kg당이 섞여 다시 틀리기 쉬워서 결제 금액을 받음)
- **중복 입력**: 같은 날·품목·구매처(공백·대소문자 무시)가 있으면 "○○님이 언제 이미 등록" 경고. 저장은 막지 않음(같은 날 다시 사는 경우 있음).
  - 날짜 앞뒤 며칠까지 넓히는 안은 사용자가 거절(앞뒤로 같은 걸 사는 경우가 있음).
  - 같은 구매를 두 번 넣으면 수량을 늘려 버리던 "수량 합산" 버튼은 제거.
- 팀 운영 권장(기능 외): **결제한 사람이 입력**, 입고일 기준(결제일/수령일)을 하나로 정하기.

## 남은 결정·아이디어
- 입고일 기준(결제한 날 vs 받은 날) 팀 합의 → 날짜 칸 안내 문구에 반영.
- 같은 가게가 다른 이름으로 들어가는 문제(예: 지점명 포함/미포함) → 구매처 이름 통일 규칙.
- 식자재 품질검증 시스템과 판정 기능이 겹침 → 역할 분담(이 보드 = 샘플 구매·빠른 판정, 품질검증 = 정식 보고서) 또는 연동 검토.
- 이미 들어간 중복을 찾는 "중복 의심 목록"은 데이터가 쌓인 뒤 필요하면 추가.

## 개발 메모 (실수 방지)
- lucide-react는 0.263.1 UMD를 쓰므로 최신 아이콘 이름이 없을 수 있음(`UserRound` 없음 → `User`). 없는 아이콘을 쓰면 화면 전체가 멈춤.
- JavaScript에서 `null >= 0`은 `true`. 빈칸(null)을 숫자와 비교하기 전에 반드시 null 확인.
- `app.js`는 빌드 결과물. 항상 `src/app.jsx`를 고치고 `node build.js`.
